# REVIEW.md

Defects found in the starter `app/main.py`. Each was checked against `openapi.yaml` (rules R1-R10) and `DATA_MODEL.md`.
Items marked (verified) were reproduced by running the code.

| # | Where | What is wrong | How you'd notice it | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses `int(seconds/60)` then `> 10`, so 09:40:01 gives 10.01 -> 10 -> not > 10 -> returns 0. R2 says strictly more than 10:00 after shift start is late, so it should return 10. (verified) | Punch in at 09:40:01 on a 09:30 shift: expected 10, got 0 | Compare elapsed seconds `> 600`, then `late_minutes = elapsed_seconds // 60` |
| 2 | `compute_late_minutes`, `punch_in` | `punch_in.replace(hour=h, minute=m)` is applied to a naive/local/UTC time, not IST. Shift start is an IST wall-clock time. Overnight shifts (R1) are not handled, so the shift start would be on the wrong day. | Punch-in stored as UTC 04:05 (09:35 IST) is compared to 09:30 as if both were the same zone | Convert the instant to IST first, compute the attendance date per R1, build `shift_start` on that date in IST, then subtract |
| 3 | `compute_work_hours` | Python `round()` is banker's/float rounding. R4 requires half-up to 2 decimals (e.g. 2.675 must give 2.68, got 2.67). Seconds are not truncated first (R1). (verified) | Work hours of exactly x.xx5 | Truncate both instants to whole seconds, use `Decimal(seconds)/3600` with `ROUND_HALF_UP` |
| 4 | `compute_overtime` | Mixes a tz-aware `end` with a naive `punch_out`, which raises `TypeError` (verified). No 30-minute minimum (R3), so 5 minutes of overtime is reported. No overnight handling (shift end falls next day). | Any punch-out call; or 10 min after shift end returns 10 not 0 | Make all datetimes tz-aware, return 0 unless floor minutes >= 30, put shift end on the next day for overnight shifts |
| 5 | `punch_in` | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises `TypeError` -> 500. Spec says 404. | POST with an `emp_code` that does not exist | Return 404 when the employee is missing |
| 6 | `punch_in` | Check-then-insert race: two simultaneous requests can both pass `find_one` and insert two documents; there is no unique index on (`emp_code`, `date`). Spec requires exactly one 201 and the rest 409. | Fire parallel identical punch-ins | Unique index on (`emp_code`, `date`) created at startup; insert and catch `DuplicateKeyError` -> 409 |
| 7 | `punch_in` | `datetime.fromtimestamp(ms/1000)` and `datetime.now()` use the server's local zone and are naive; PyMongo stores naive values as UTC, so the stored instant is wrong unless the server runs in UTC. The record `date` comes from the local date, not the IST date (R1). Milliseconds are not truncated (R1). | Run the server in a non-UTC zone; punch at 23:50 IST | Use `datetime.fromtimestamp(ms/1000, tz=timezone.utc)`, truncate to seconds, derive the date in IST |
| 8 | `punch_in` / `PunchInIn` | `status` accepts any string (should be only PRESENT/WFH/ON_DUTY). `punched_at` accepts seconds, floats and numeric strings that pydantic coerces; must be an int epoch-ms within 1e11 to 4102444800000 or 422. `if body.punched_at` treats 0 as missing. | Send `status: "ABSENT"` or `punched_at: 1783312500` | Use `Literal` for status and `StrictInt` with `ge`/`le` bounds; test `is not None` |
| 9 | `punch_in` response | Returns `id` (the Mongo `_id` as string) and raw datetimes. The API must never expose `_id`, and instants must be epoch ms. | Response has `id` and ISO-string datetimes | Serializer that drops `_id`, converts instants to epoch ms and applies defaults for missing fields |
| 10 | `create_employee` | Check-then-insert race and no unique index on `emp_code`; spec requires a unique index and exactly one 201 under concurrent creates. | Parallel duplicate creates | Unique index on `emp_code`, catch `DuplicateKeyError` -> 409 |
| 11 | `create_employee` / `EmployeeIn` | No validation: `emp_code` pattern `^EMP\d{4,6}$`, email pattern, name/department length limits, `HH:MM` format, `shift_start != shift_end`, `joined_on` a valid date. All must be 422. | POST bad code or equal shift times | Pydantic `Field` constraints plus a validator |
| 12 | `create_employee` | `created_at` is naive local `datetime.now()`, and the response returns it as a datetime instead of epoch ms. | Look at the POST response | Store tz-aware UTC; return epoch ms |
| 13 | `list_employees` | `skip = page * page_size` is off by one for 1-based pages: page 1 skips the first page. | GET `/employees?page=1` misses the first 20 employees | `skip = (page - 1) * page_size` |
| 14 | `list_employees` | `total` is `count_documents({})`, ignoring the department filter (R10). No sort (spec: `emp_code` ascending). No validation of `page >= 1` or `page_size <= 100`. | Filter by department and compare `total` | `count_documents(q)`, `.sort("emp_code", 1)`, `Query(ge=1)` and `Query(le=100)` |
| 15 | `list_attendance` | Loads every matching document into memory and sorts in Python; spec wants it fast on ~100k records. Sort is `date` desc only (must be `date` desc then `emp_code` asc). | Large collection: slow and memory-heavy | Use `.sort([("date",-1),("emp_code",1)]).skip().limit()` with a compound index; `count_documents(q)` for total |
| 16 | `list_attendance` | Exposes `_id` as `id`, returns datetimes instead of epoch ms, and legacy docs missing `half_day`/`history` come back without them. `date_from > date_to` is not rejected (422). Dates and `status` are not validated. `page`/`page_size` unbounded. | GET `/attendance` on seeded legacy data | Serializer with defaults (`half_day` false, `history` []), `Query` validation, date parsing, range check |
| 17 | startup / `/health` | No indexes created at startup (spec: idempotent). `/health` always returns ok even if MongoDB is down; spec says ping and return 503 on failure. | Stop MongoDB and call `/health` | `ensure_indexes()` at startup; `/health` pings and returns 503 on error |
| 18 | `MongoClient` | Created without `tz_aware=True`, so every datetime read back is naive. Combined with #7, instants silently shift if code compares them with aware datetimes. | Reading seeded docs and subtracting an aware datetime raises `TypeError` | `MongoClient(..., tz_aware=True)` and treat all instants as UTC-aware |

## Looked at and decided not defects
- `IST = timezone(timedelta(hours=5, minutes=30))` is correct (no DST in India).
- `load_dotenv()` does not override real environment variables by default, so real env vars win, as required.
- `doc.pop("_id", None)` after `insert_one` is fine: PyMongo adds `_id` to the dict, and removing it keeps it out of the response.
- Synchronous PyMongo inside plain `def` endpoints is fine: FastAPI runs them in a threadpool and `MongoClient` is thread-safe.
